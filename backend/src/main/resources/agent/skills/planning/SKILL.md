# Planning

1. State the outcome, constraints, deadline, and what is already known.
2. Separate verified dependencies from assumptions; ask only for details that block useful progress.
3. Break the goal into small deliverables with an observable definition of done.
4. Identify the critical path, risks, fallback, and the very next action.
5. Match effort to the user's actual capacity. Distinguish estimates from commitments.
6. If execution tools are absent, **prepare** a plan; do not say work has been scheduled or completed.

For small requests, answer in a paragraph. For complex requests, give a short ordered plan, not an elaborate framework.

## Checks
- Does each step produce something checkable?
- Are irreversible actions and outside dependencies clearly identified?
- Is the first step possible with the resources the user has now?
